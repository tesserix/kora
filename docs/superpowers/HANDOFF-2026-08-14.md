## Process that earned its keep — please keep doing this

**1. A green test proves nothing until you have seen it fail.** Three separate times this session a
test passed for the wrong reason:

- Two `AskAgainSheet` tests passed *with the guards deleted* — the mutation callbacks ran outside
  `act()`, so React never flushed and the assertion could not fail.
- `TestLocalDayRejectsGoZeroTime` used `INSERT ... SELECT FROM users LIMIT 1`, which inserts ZERO
  rows on an empty database. It passed locally (dev DB has users) and failed on CI. **This kept
  `build-image` skipped for five runs**, which is the actual reason no image existed to deploy.
- `TestLocalDayBackfillMatchesProfileZoneForExistingRows` counted mismatches across `food_logs`, so
  on an empty DB it returned 0-of-0 and reported PASS while verifying nothing. It now skips.

Deliberately break the implementation, watch the test go red, restore. Every time.

**2. Run the suite against an EMPTY database, not just the dev one.** `createdb`, `go run
./cmd/migrate`, `TEST_DATABASE_URL=<scratch> go test -count=1 -p 1 ./...`. That is what CI does, and
it is where ambient-data assumptions surface.

**3. `-count=1` is mandatory after a schema change.** Go's test cache hid a real constraint
violation this session.

**4. Watch CI after every push.** Five red runs went unnoticed because nobody looked.

**5. Verify a deploy did what you think.** The first Redis sidecar deployed cleanly, went `2/2
Running`, and the cache was still disabled — Kubernetes starts regular containers in parallel and
kora-api probes Redis once at boot, so it lost a 3-second race. Only the pod logs showed it.

## Repo traps confirmed or discovered today

- **Never reintroduce `@react-native-firebase/*` or `useFrameworks`.** RNFirebase needs
  `useFrameworks` for SPM; under frameworks `react-native-screens` cannot import the private React
  header `React/RCTSurfaceTouchHandler.h` and the iOS build dies. Proven: builds #14/#15 finished,
  the Crashlytics commit landed, #16 failed on that header, #18 finished once both were removed.
  `useFrameworks: "static"` is not an escape (expo/expo#39080). Firebase **auth** is fine — that is
  the JS SDK, no pods.
- **After ANY dependency change, regenerate the lockfile with `npx npm@10.9.3 install
  --package-lock-only`.** Local npm is 11.x, EAS runners use 10.9. Caught live today: npm 11 omitted
  `@bacons/apple-targets/node_modules/typescript` and the remote `npm ci` would have failed.
- **Sentry:** do NOT set `SENTRY_URL`. Organization auth tokens embed their own region and
  `sentry-cli` prefers it — setting it added a warning and changed nothing. Org tokens have the
  fixed scope `org:ci`; `project:releases` is a personal-token scope. `@sentry/wizard` cannot run in
  the agent harness or via `!` (no TTY) and would add a second `Sentry.init` colliding with
  `src/observability/sentry.ts`.
- **The simulator cannot get past sign-in** without real credentials — no dev-auth bypass exists.
  To test a signed-in screen, complete onboarding directly in the dev DB
  (`update users set ... onboarded_at=now()`), which is what unblocked #83's runtime verification.
- **`idb` synthetic taps do not drive the custom `ToggleSwitch`** (navigation Pressables are fine).
  Its a11y frames are content-space, so a control below the fold reports a y beyond the 874pt screen.
- Something in the harness **rewrote ASCII `''` to a smart quote `”`** in three Go comments between
  two commits. Restored in `5e89da9`; worth watching, since in a string literal it would be a bug.
